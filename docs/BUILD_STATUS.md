## Build commands

### Android (from a clean clone, or in CI)

```sh
cd apps/android
./gradlew :app:assembleDebug      # debug APK only
./gradlew :app:testDebugUnitTest  # JVM unit tests
```

- Project: `OmSuite`, module `:app`, namespace/applicationId
  `com.omsuite.android`, compileSdk 34, minSdk 26, targetSdk 34,
  versionCode 1, versionName `0.1.0-debug`.
- Toolchain: AGP 8.5.2, Kotlin 1.9.24, KSP 1.9.24-1.0.20, Gradle 8.7,
  Compose BOM 2024.06.00, Navigation 2.7.7, Room 2.6.1, DataStore
  Preferences 1.1.1, DocumentFile 1.0.1.
- `./gradlew` is a bootstrap script, not the stock wrapper jar (the stock
  `gradle-wrapper.jar` is not vendored because this VM cannot run Java to
  generate it). It downloads Gradle 8.7 once into
  `~/.gradle/wrapper/omsuite-gradle-8.7/` and execs it. CI uses the same
  script; it may be replaced with a generated wrapper + jar later.
- **Signing: debug only.** The debug APK uses the debug signing key
  generated by the Android Gradle plugin. No release keystore is committed,
  no release signing is configured, and no release APK is claimed.

## Known failures (exact)

1. **Android local build — not attempted, blocked:** no Java in the VM
   (stream 2: `which java kotlin gradle` → no output;
   `ls /usr/lib/jvm` → `No such file or directory`). No JDK download was
   attempted: the coordinator plan already records local Gradle as
   platform-blocked, and CI is the designated route.
2. **Windows NSIS installer on this VM — FAILED:**
   `wine process failed ENOENT` / `Exit code: ENOENT. spawn wine ENOENT`
   from `electron-builder@26.18.0 --win nsis --x64` (two attempts; both
   reached `dist/win-unpacked/` at 357 MB before the NSIS step failed).
   No workaround was attempted (installing Wine system-wide would still
   leave the installer unverified on Windows).
3. **Electron first launch as root — VM quirk, not an app bug:**
   `Running as root without --no-sandbox is not supported` (SIGTRAP).
   All later launches used `ELECTRON_DISABLE_SANDBOX=1`; Windows users
   do not need this.
