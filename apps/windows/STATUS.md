## 5. Blockers (exact error text)

**Blocker B1 — Windows NSIS installer cannot be built on this Linux VM.**
electron-builder's NSIS target shells out to Wine on Linux, and Wine is not
installed here. Exact failure from the second attempt:

```
⨯ wine process failed ENOENT
Exit code:
ENOENT
Output:
Exit code: ENOENT. spawn wine ENOENT  failedTask=build stackTrace=Error: wine process failed ENOENT
```

What was attempted: two full `electron-builder --win nsis --x64` runs (see
§2); both got as far as producing `dist/win-unpacked/` (357 MB, Windows exe +
Electron runtime, deleted) before the NSIS step failed. What a Windows build
machine needs: Windows 10/11 x64, Node.js 20+, then
`powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1`
(or `npm install` + `npx electron-builder@26.18.0 --win nsis --x64`).
No workaround was attempted on this VM (installing Wine system-wide is
outside this stream's scope and would still leave the installer unverified
on Windows). The partial 190,333-byte `OmSuite-Setup-0.1.0.exe` was deleted.

**Non-blocker, recorded:** running Electron as root in this VM requires
`ELECTRON_DISABLE_SANDBOX=1` (see §2). This affects only VM smoke testing,
not Windows users.

## 6. Limitations (also in README.md)

- No custom app icon: packaged builds use Electron's default icon. nimu has
  not picked an OmSuite Windows icon; do not invent one from the prototypes
  (the prototypes contain no icon asset).
- Unpacked Windows build size observed: 357 MB for `win-unpacked/` (Electron
  45 runtime + app). Installed size and installer size are Not Tested —
  the NSIS installer was never completed, so no installer size is claimed.
- Editor limit: files over 10 MB and binary files are refused (by design).
- Folder size counting caps at 200,000 entries and reports truncation.
- Copy/move never overwrite: a clash gets a ` - Copy` name. This is a
  deliberate data-loss guard, and differs from Explorer's overwrite prompt.
- Markdown preview is a subset (see README.md); tables, footnotes, and
  embedded HTML are not rendered (HTML is escaped, not passed through).
- Renderer find/replace duplicates the tested `text-core` algorithm in
  browser JS (the renderer cannot `require` Node modules); the core
  functions carry the unit tests, the renderer copy is smoke-verified only
  by the launch check, not by a UI test. A UI-level test on Windows is still
  owed.
- Prototype "green" theme was NOT carried over: only light/dark/system ship,
  per the brief's theme scope. The prototype's Tailwind CDN is NOT shipped.
- Settings file location on Windows (`%APPDATA%\OmSuite`) is derived from
  Electron's `app.getPath('userData')` and is Not Tested on Windows itself.

## 7. Handover checklist for the Windows build machine

1. Copy this folder to a Windows 10 (1809+) / 11 x64 machine with Node.js 20+.
2. `npm install` then `npm start` — verify the app opens on your Home folder.
3. `npm test` — expect 17/17 pass.
4. `powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1` —
   expect `dist\OmSuite-Setup-0.1.0.exe`. This step has never succeeded
   anywhere yet; its first success will be on that Windows machine.
5. Install the exe on a second (recipient-style) PC, expect a SmartScreen
   warning (unsigned build), and walk through: Files (all operations),
   Editor (save/Save As/JSON/Markdown preview), Settings (theme/save
   location/recents/cache). Record results before sharing the installer.
